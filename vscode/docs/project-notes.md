# Project notes

- `npm run pictures` needs Playwright's Chromium with its system libraries (`libglib-2.0.so.0` and others). The agents' sandbox lacks them and cannot install them, so retaking the README GIFs is a person's step, never an agent's.
- The side bar shortcuts (`Control+b`, `Control+Alt+b`) toggle, so a bar that starts hidden opens on a fresh machine (the secondary side bar showed an empty CHAT panel in every picture). `test/pictures/take.ts` therefore hides each bar through one helper (`hideSideBar`) that does nothing when the bar's part is off screen. On a busy machine a bar can hide by itself while the palette opens (the empty CHAT view container resolves), and the palette lists `View: Close Primary Side Bar` / `View: Hide Secondary Side Bar` only while its bar is visible; so the helper waits for the palette to be open, then for the command row or the bar going away, whichever comes first: it picks the row, or closes the palette with Escape and logs that the bar hid by itself. With neither within the timeout it stops with an error naming both. Afterwards `prepare()` checks that both bars are off screen before the first picture, or stops with an error naming the bar.
- `test/pictures/take.ts` waits on editor state, not on fixed pauses: each step waits (with `waitForState`, a timeout and an error naming the state; clicks go through `clickWhenReady`, and locator reads in `pointAt` sit behind a `waitForState` guard) for the row in the palette, the focused editor, the hover text, the completion item, a hover or list being fully shown (`widgetShown`: opaque, no running animation), the status bar text or the side bar going away. The only fixed waits left are in `holdFrame` and `typeText`; they pace what a GIF shows (frame holds and the typing delay), not the editor. A GIF's clock is the script's pacing, not the wall clock: `Recording` advances a virtual clock (`src/gif_timeline.ts`) only while `holdFrame` runs, stamps each screencast frame with it and samples it every `GIF_TICK_MS`, so a slow machine cuts out its stalls and the GIF plays the sum of its holds. The hold plans and `GIF_TYPING_MS` live in `src/gif_plans.ts`, which `take.ts` imports and `src/gif_plans.test.ts` sums. The planned lengths are `colors.gif` 4 480 ms (200 + 46 characters × `GIF_TYPING_MS` 80 + 600) and `completion.gif` 3 000 ms; the recording stops with an error naming the GIF at 8 seconds or more. `src/picture_script.test.ts` fails when a `waitForTimeout` or `pause(` call appears anywhere else.
- When the picture script stops after the page exists (a wait gives up, or any other error after `page.goto`), `main()` saves a full-page screenshot, with its own 5 s timeout, to `out/pictures/gave-up.png` under the repository root, prints `pictures: the page when the script stopped: out/pictures/gave-up.png` on stderr before the error line, and rethrows the original error. If the screenshot fails too, it prints one line saying so. The file never goes through `save()` and never lands in `images/`; `out/` is ignored by git, so it never reaches a commit.
- Product behaviour and its tests come first. The picture script's own guards (`test/pictures/take.ts` and `src/picture_script.test.ts`) are not to be extended, and reviewers do not suggest more of them: the store pictures are not retaken each release.
