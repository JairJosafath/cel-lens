# Project notes

- `npm run pictures` needs Playwright's Chromium with its system libraries (`libglib-2.0.so.0` and others). The agents' sandbox lacks them and cannot install them, so retaking the README GIFs is a person's step, never an agent's.
- The side bar shortcuts (`Control+b`, `Control+Alt+b`) toggle, so a bar that starts hidden opens on a fresh machine (the secondary side bar showed an empty CHAT panel in every picture). `test/pictures/take.ts` therefore runs `workbench.action.closeSidebar` and `workbench.action.closeAuxiliaryBar` and checks that the secondary side bar is off screen before the first picture, or stops with an error.
- `test/pictures/take.ts` waits on editor state, not on fixed pauses: each step waits (with `waitForState`, a timeout and an error naming the state) for the row in the palette, the focused editor, the hover text, the completion item, a hover or list being fully shown (`widgetShown`: opaque, no running animation), the status bar text or the side bar going away. The only fixed waits left are in `holdFrame` and `typeText`; they pace what a GIF shows (frame holds and the typing delay), not the editor. A GIF's clock is the script's pacing, not the wall clock: `Recording` advances a virtual clock (`src/gif_timeline.ts`) only while `holdFrame` runs, stamps each screencast frame with it and samples it every `GIF_TICK_MS`, so a slow machine cuts out its stalls and the GIF plays the sum of its holds. The planned lengths are `colors.gif` 4 480 ms (200 + 46 characters × `GIF_TYPING_MS` 80 + 600) and `completion.gif` 3 000 ms; the recording stops with an error naming the GIF at 8 seconds or more. `src/picture_script.test.ts` fails when a `waitForTimeout` or `pause(` call appears anywhere else.
